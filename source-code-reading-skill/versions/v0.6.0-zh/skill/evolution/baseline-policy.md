# Skill 演进基线规范

## 核心不变量

**演进必须基于合并，而不是重写。** 新版本默认从上一发布版本的完整资产集开始，并保留已有能力。

## 发布流程

```text
上一版本
      ↓
能力清单
      ↓
基线文件/能力对比
      ↓
最小增量补丁
      ↓
完整性回归
      ↓
语义回归
      ↓
变更日志
      ↓
发布
```

## 必须执行的检查

### 1. 能力清单

记录基线中的能力、参考资料集合、模板、案例、示例和测试。

### 2. 文件保留

除非某文件出现在明确批准的移除记录中，否则基线中的每个文件都必须在候选版本中继续存在。

### 3. 能力保留

文件仍然存在，并不意味着其中的能力没有消失。因此既要比较文件清单，也要比较人类可读的能力清单。

### 4. 最小补丁

优先增加或编辑最相关的最小章节。不要仅仅为了简化包结构，就重写无关的参考资料。

### 5. 移除协议

任何移除都必须记录：

```yaml
removal:
  path: ""
  capability: ""
  reason: ""
  replacement: ""
  regression_evidence: []
  approved: false
```

### 6. 回归

至少运行完整性测试，以及 `evolution/regression.md` 中描述的语义回归套件。

## 什么算回归

例如：

- 知识源注册表消失；
- gold/failure 案例消失；
- 图表选择目录丢失关键语义区分；
- trace 深度或 claim 验证能力消失；
- 文档规范变得过弱，无法指导源码笔记；
- architecture ↔ topic ↔ source 的集成关系不再明确。

## 版本规则

如果一个修复版本的主要目的，是恢复之前丢失的行为，而不是有意重新设计模型，可以使用 `x.y.1` 这样的版本号。
