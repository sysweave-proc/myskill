# 文档规范

## 目的

源码阅读文档是**经过验证的知识图谱的一个视图**，针对特定问题和读者进行优化。

## 推荐骨架

```text
# 标题

> 核心问题

## 系统位置

## 一句话模型

## 1. 核心对象

## 2. 核心路径 / 行为

## 3. 状态 / 生命周期

## 4. 并发 / 资源 / 约束

## 5. 关键实现

## 6. 源码导读

## 7. 关键结论

## 8. 下一步阅读
```

只包含 Pattern Profile 支持的章节。

## 系统位置

对于大型系统，展示缩放路径：

```text
System → Subsystem → Path → Topic
```

这一部分用于定位，不要重复整个架构 Atlas。

## 一句话模型

在细节之前，先给出最小且准确的心智模型。

## Primary View

把主导表达放在读者真正需要它的位置附近。

## 对象卡片

为重要实体使用紧凑卡片：

```text
### BufferDesc

职责：...
关键字段：...
管理者：...
生命周期：...
```

## 源码片段

使用短小且有明确目的的代码片段。片段必须有理由：结构、分支、迁移、锁、ownership、清理或其他决定性证据。

## 源码导航

每个重要主题都应该有类似下面的路径：

```text
当前概念
  → 当前符号
  → 下一个符号
  → 为什么继续
```

## 跨章节链接

优先引用规范化的共享引用，而不是复制定义。笔记应该像共享图谱上的一个窗口。

## 风格

优先使用准确的源码名称、面向条件的正文、简洁段落、用于紧凑属性的表格，以及只有在能降低认知负担时才使用的图。

避免源码倾倒、模板化套话、过度赞美式正文、没有证据的意图判断，以及为了装饰而画图。
