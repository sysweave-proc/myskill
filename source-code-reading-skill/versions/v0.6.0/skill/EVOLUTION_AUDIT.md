# v0.1–v0.5 Evolution Audit

## Executive conclusion

- **v0.1 → v0.2:** normal additive evolution. Diagram/representation semantics were substantially expanded; no material capability loss detected.
- **v0.2 → v0.3:** normal additive evolution. External knowledge-source registry was added.
- **v0.3 → v0.4:** architecture/evolution capabilities were added, but two earlier assets were lost: the general `references/tracing/exploration-policy.md` and the `knowledge-sources/README.md`. The first is a material process capability and is restored here; the second is documentation-level and is also restored.
- **v0.4 → v0.5:** material regression. The package was rebuilt from a much smaller subset, dropping architecture detail references, knowledge sources, evolution/cases, diagram catalog, tracing/validation/document policies, templates, and examples. The concepts were partially restated in a smaller `SKILL.md`, but the reusable rule assets themselves disappeared. This is not healthy evolution.

## Important features restored/preserved in v0.5.1

1. System Atlas + Canonical Knowledge Graph + one-model-many-views.
2. Architecture → Path/Scenario → Mechanism → Entity → Symbol → Source integration.
3. Detailed knowledge model and semantic relation families.
4. Pattern catalog and representation/diagram selection policy.
5. Historical diagram/tool decision knowledge.
6. Claim/Evidence/Trace model, `FACT/INFERENCE/INTERPRETATION`, and `D1/D2/D3`.
7. Validation V1–V6 and targeted re-entry.
8. Document policy, source navigation, snippets, and reader checks.
9. Knowledge-source registry and external-source authority boundaries.
10. Gold/failure cases, anti-patterns, feedback taxonomy, rule proposals, regression.
11. Progressive execution gates and L0–L3 depth controls.
12. Merge-based Skill evolution with baseline inventory and integrity regression.

## Deliberately treated as normal consolidation

Some historical diagram material was shortened in v0.4 (for example, less-central legacy/optional visual forms). The core semantic distinctions and decision policy survived. These were not treated as material capability loss.

## New hard invariant

> A Skill version must preserve the previous release's capabilities by default. A new version is a merge, not a clean-room rewrite.
