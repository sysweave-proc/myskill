# 校验 · Validation

没有校验，整条流水线只是一个生成器。

## 六层校验

### V1 结构
- 核心问题存在；
- 适用时有架构位置；
- 有用时有主视图；
- 有源码导航；
- 有用时有"下一步阅读"。

### V2 语义
- 实体关系有支撑；
- ownership 没和 referencing 混淆；
- flow 没和 call graph 混淆；
- 状态迁移是真实的；
- 同步对象是真实的；
- 数据移动在重要处区分了 copy / reference。

### V3 可追溯
每条主要结论都能走通：

```text
Claim → Evidence → Source Anchor
```

### V4 表达
- 主表达与主导模式匹配；
- 图没有过载；
- 图没有重复正文；
- 渲染器有能力表达所选语义；
- 需要精度时用了专业工具。

### V5 读者 / 导航
读者应能回答：

```text
我在哪？
核心机制是什么？
它为什么重要？
哪条路径会用它？
源码在哪？
下一步读什么？
```

### V6 架构一致性
- 主题坐标能落在当前 Atlas 上；
- 源码证据与架构不矛盾，或矛盾已被记录；
- 关键路径上没有未解释的缺口。

## 返修路由（回到最小受影响阶段，不整体重做）

```text
缺 scope/上下文    → ① Scope & Explore
缺知识             → ② Knowledge Model
抽象/模式选错      → ③ Pattern Recognition
结论无支撑         → ④ Traceability
图/文档不好        → ⑤ Representation & Document
跨层不一致         → ⑥ Validation，再按需回到更早阶段
```

## 读者导航的固定三问

任何一篇笔记交付前自问：

```text
1. 概念 → 关系 → 源码，这条路径走得通吗？
2. 每个图的每个节点，读者能顺着找到代码吗？
3. 结论里有没有哪一句是"我猜的"却没被标出来？
```

第 3 问失败即视为 V3 失败，必须回到追踪阶段。
