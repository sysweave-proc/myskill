# v0.1–v0.5 演进审计

## 结论

- **v0.1 → v0.2：** 正常的增量演进。图表/表达语义得到大幅扩展；未发现实质性的能力损失。
- **v0.2 → v0.3：** 正常的增量演进。新增了外部知识源注册表。
- **v0.3 → v0.4：** 增加了架构与演进能力，但丢失了两个早期资产：通用的 `references/tracing/exploration-policy.md` 和 `knowledge-sources/README.md`。前者属于实质性的流程能力，已在此恢复；后者属于文档级资产，也已恢复。
- **v0.4 → v0.5：** 出现实质性回归。该版本从一个小得多的子集重新构建，丢失了架构细节参考、知识源、演进/案例、图表目录、追踪/验证/文档规范、模板和示例。概念虽然部分重新写进了更精简的 `SKILL.md`，但可复用的规则资产本身消失了。这不属于健康的演进方式。

## v0.5.1 恢复/保留的重要能力

1. System Atlas + 规范知识图谱 + 一份模型多种视图。
2. Architecture → Path/Scenario → Mechanism → Entity → Symbol → Source 的集成。
3. 详细知识模型与语义关系族。
4. Pattern 目录以及表达/图表选择规范。
5. 历史图表/工具决策知识。
6. Claim/Evidence/Trace 模型、`FACT/INFERENCE/INTERPRETATION` 以及 `D1/D2/D3`。
7. V1–V6 Validation 与定点重新进入流程。
8. 文档规范、源码导航、代码片段和读者检查。
9. 知识源注册表以及外部来源的权威边界。
10. Gold/failure 案例、反模式、反馈分类、规则提案、回归。
11. 渐进式执行闸门以及 L0–L3 深度控制。
12. 基于 Merge 的 Skill 演进，以及基线清单和完整性回归。

## 有意视为正常整合的变化

部分历史图表材料在 v0.4 中被缩短，例如不再强调一些非核心的 legacy/optional 视觉形式。核心语义区分和决策规范仍然保留，因此这些变化不视为实质性的能力损失。

## 新的硬性不变量

> 一个 Skill 版本默认必须保留上一版本的能力。新版本是 Merge，而不是从零重写。
